### Phase convention (item 2)
SPECS waveguides apply `exp(+j beta L)`: the transmission phase grows with frequency, `tau = +dphi/domega`.

| Format | Time convention | Conversion | Evidence |
|---|---|---|---|
| Lumerical/SiEPIC `.sparam` | physics, `exp(-i omega t)` | none | Lumerical's FFT convention (forward transform with `exp(+i omega t)`, i.e. fields `exp(-i omega t)`); the SiEPIC `EBeam_1550_TE_BDC.sparam` (Simphony repository) has transmission phases that grow with frequency, dphi/domega = +0.96 ps |
| Touchstone | RF engineering, `exp(+j omega t)` (delay line `exp(-j omega tau)`, scikit-rf) | complex conjugate | standard RF convention |
| CSV | physics (SAX, gplugins key `in@0,out@0`) | none | SAX waveguide `exp(+j 2 pi neff L / lambda)` |
| Taylor form | SPECS | none | own format |

`convention=physics|engineering` overrides the default (e.g. a Touchstone file written by a photonics tool with
the physics convention). Proof (`tests/sparam/test_sparam.py`, meson suite `sparam`): `tests/sparam/gen_fixtures.py`
writes a 100 um waveguide (neff 2.2, ng 4.2, 10 dB/cm, exactly SPECS's WG formula) in each format, in that
format's own convention. Through `SPAR` each gives the field of a `WG` of the same length:

- `.dc`: <= 3.6e-13 at 41 grid points and at 143 points between grid points (the phase is linear in frequency,
  so the linear interpolation is exact). Taylor form: <= 1.9e-12.
- `.tran`: pulses at two wavelengths leave at the same times (1 ps + L*ng/c = 1.40097 ps rounded to 1.4 ps),
  with the same fields (<= 1.2e-13).
- The Touchstone fixtures read without the conjugation differ by 1.97 (field), so the conversion is needed.

## Decisions I had to take (conservative, not covered by the decisions file)
1. **Delay per output port, not per path.** With absolute writes and a delay per (input, output) pair, an input
   event written with a short delay can be followed by an older event written later with a longer delay. That
   older value would then leave a stale output, wrong even in steady state. So `delay=auto` uses, per output and
   wavelength, the group delay of the largest path into that output (|S| at that wavelength), and every write to
   that output uses it. Steady state is exact; paths with different delays into one output arrive together
   (documented). `delay=none` and `delay=<s>` (one delay everywhere) are also available.
2. **Negative group delays become 0** (causality). They are reported once per device in `.tran` when they are at
   least half a time step (the ring's through port near resonance gives -14.5 fs).
3. Auto delays that round badly give the B-014 **warning** (data-derived, like the delays a device creates
   internally). A `delay=<s>` written in the netlist that rounds to 0 is an **error**, like a WG's length.
4. **Unidirectional roles as COUPLER**: with an even net count and no bidirectional net, the first half are
   inputs and the second half outputs. An odd count, or a bidirectional net, makes the device bidirectional. In
   uni mode the input-to-input paths (reflections) are dropped, with one warning when above -40 dB.
5. **One `SC_METHOD` sensitive to every input**, rather than one process per input port (the brief). In one
   delta cycle it handles each input with an event, in net order, and gives the same outputs.
6. Taylor form designed anew: plain polynomial coefficients in `d = lambda - lambda0`, not the derivatives of
   the old `TransmissionMatrix`. The `range` line is mandatory (out of range is an error), `delay` is optional
   (derived from the phase), and the first line is `specs-taylor 1` for versioning.
7. CSV form: SAX/gplugins key (`"<in>@0,<out>@0_re"`, quoted), mode 0 only, physics convention.
8. Not supported, rejected with an error: Lumerical group-delay headers (7th field), multimode data, block types
   other than `transmission`, Touchstone Y/Z/H/G, mixed-mode, noise data (skipped).
9. Passivity: checks the output power for each input (column sums, a necessary condition, not the largest
   singular value), with INTERCONNECT's 1.03 threshold. Default `check` warns; `enforce` is a uniform
   scaling where the sum exceeds 1.
10. Range ends get a relative tolerance of 1e-12 (the wavelength-matching constant).
11. The file path is resolved like `.include`: next to the netlist first, then the cwd. The data file is not
    added to the run manifest, which keeps its meaning of netlist files only (see below).
12. Export written in Python (stdlib) as a tool, not in the C++ engine. Formats: `.sparam`, Touchstone 1/2 and
    CSV; no `.npz` and no Taylor export. Its default tolerances are `abstol=1e-12 reltol=1e-9`.
13. String keyword values need quotes (`format="touchstone"`), as the grammar requires for strings.
14. The SiEPIC BDC fixture is **not committed**. Simphony's LICENSE is MIT but puts its "resources" under other
    terms in a NOTICE.txt that no longer exists (404). The brief's `cir/spar_bdc` case is therefore replaced by
    the exported add-drop ring.

## Found, not done
- **Interpolating magnitude and phase separately is poor near transmission nulls** (0.02 field error at the
  add-drop through null on a 0.05 nm grid, vs. 1e-4 elsewhere). The brief chose this method, after gplugins.
  Interpolating real/imaginary parts near low |S|, or a hybrid, would be better there. That is a numerics
  choice for the maintainer (needs-human).
- The run manifest (F-01) does not hash the S-parameter data files: a changed file gives an identical manifest.
- In `delay=auto` the dominant path into an output is chosen by |S| among all inputs, also inputs that carry no
  light (e.g. the unused `add` port).
- Exciting an output of a unidirectional subcircuit during export makes it bidirectional for that sweep
  (documented in `doc/sparam.md`; same values for SPECS's reciprocal devices).
- Not implemented from the brief: reciprocity fill, `.npz` export, `delay` per path, phase 2 (FIR/IIR,
  needs-human).
- `doc/netlist.md` only mentions `.param` in subcircuit bodies; `.assign` works there too (the ring uses it).
- AGENTS.md says clang differs from the baseline in 6 cases; the strict clang check fails 7 (`cir/add_drop`,
  `opt/tol-resolution-overrides`, `opt/mode-fd`, `opt/multi-file`, `regress/b004-mode-td-dc`,
  `regress/f05-format-vcd-csv-dc`, `regress/f15-stats-dc`), identically before (cb3a5c3) and after.
- `parser.l` "dangerous trailing context" flex warning (pre-existing; line moved by the new rule).
